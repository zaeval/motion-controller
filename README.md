# Motion Controller

웹캠으로 손 제스처를 읽어 macOS를 조작하는 메뉴바 앱. Apple Vision의 손·몸 포즈 인식만 쓰고,
영상은 메모리에서만 처리하고 전송하지 않는다. 얼굴을 등록하면 얼굴 특징 벡터를, 잠긴 화면에서 누군가 입력을
시도하면 그 사진을 이 Mac에 저장한다.

## 무엇을 할 수 있나

| 모드 | 들어가는 방법 | 할 수 있는 것 |
|---|---|---|
| IDLE | 사람이 5초 안 보이면 자동 / ✊ 뒤로 빼기 | 모드 전환 제스처만 인식 |
| 제스처 | ✊✊ 양손 주먹 2초 유지 | ✊ 주먹으로 카메라를 두 번 노크 → 재생/정지, 🤟 세 손가락 위/아래 → 확대/축소 (새끼손가락은 접어야 한다), 핀치 후 ↕ 볼륨 / ↔ 밝기 |

확대/축소는 macOS가 켜 둔 방식에 맞춰 보낸다. **화면 확대는 손쉬운 사용 기능이고 두 스위치 모두 기본이
꺼져 있다** (`com.apple.universalaccess`의 `closeViewScrollWheelToggle`, `closeViewHotkeysEnabled`).

| 켜져 있는 설정 | 앱이 보내는 것 | 결과 |
|---|---|---|
| 스크롤 제스처 + 보조 키 | ⌃ + 스크롤 | 화면 확대, 부드럽게 |
| 키보드 단축키 | ⌥⌘= / ⌥⌘- | 화면 확대, 단계별 |
| 둘 다 꺼짐 | ⌘+ / ⌘- | 앞에 있는 앱만 확대 (설정 불필요) |

튜토리얼의 확대/축소 단계에 지금 무엇으로 보내는지 표시되고, **시스템 설정의 해당 패널을 여는 버튼**이 있다.
켜면 다음 제스처부터 바로 적용된다.
| 데스크탑 전환 | 🖐 손바닥 보이면 바로 | 좌우로 쓸기만 인식 (화면에 보라색 테두리가 뜬다). 다른 손 모양을 하면 바로 제스처 모드로 돌아온다 |
| 커서 | ☝️ 검지 두 번 톡톡 | 검지를 살짝 굽힌 동안에만 커서가 **검지 손끝**을 따라감, 톡 = 클릭, 톡톡 = 더블클릭, ✌️에서 검지 톡 = 우클릭, 핀치 = 드래그, ✌️ 위/아래 = 스크롤, 🤟 세 손가락 위/아래 = 확대/축소 |

**두 손으로 쓰기 (커서 모드).** 커서를 움직이기 시작한 손이 커서를 계속 잡고, **반대손의 손 모양이 버튼**이 된다.
커서 손은 모양을 바꿀 필요가 없으니 클릭할 때 포인터가 흔들리지 않는다.

| 반대손 | 동작 |
|---|---|
| ☝️ 검지 하나 | 클릭 (빠르게 두 번 보이면 더블클릭) |
| ✌️ 두 손가락 | 우클릭 |
| ✊ 주먹 | 누른 채 유지 → 커서 손을 움직이면 드래그, 손을 펴면 놓기 |
| 🖐 손바닥 위/아래 | 스크롤 |

주먹과 손바닥은 모양 자체로 동작하고, 클릭 두 개는 **손가락을 굽혔다 펴는 것**으로 동작한다 — 손을 올리는 건
자리를 잡는 것이지 명령이 아니기 때문이다. 그래서 손을 내리지 않고 계속 클릭할 수 있다. 굽히는 동안에는 손 모양
판정을 멈추므로, 굽힌 검지가 순간적으로 주먹으로 읽혀 눌리는 일은 없다 (0.45초 넘게 굽힌 채 두면 그건 접은
것으로 보고 그 길이를 새 기준으로 삼는다). 반대손이 사라지면 잡고 있던
버튼은 놓는다. 커서 손을 내리고 1초 뒤에 다른 손을 쓰면 그 손이 커서를 잡는다. 한 손만 보일 때는 지금까지와
똑같이 그 손이 전부 한다.

✊✊ **양손을 모두 주먹 쥐고 2초 들고 있으면** IDLE·커서·데스크톱 어디서든 제스처 모드로 간다 (사용자 요청
2026-09-21). 그 전에 잠깐 쓴 '주먹 뒤로 빼기 토글'은 일부러 하기가 너무 어려웠다. 두 손이 동시에 주먹인
건 다른 어떤 제스처와도 겹치지 않는다. 어느 한 손이 0.3초까지 인식에서 빠져도
유지가 끊기지 않는다. 커서 모드에서는 반대손 주먹이 '누름'이지만, 커서 손도 주먹이면 누르지 않고 양손 주먹으로
본다. ✊ 주먹을 쥔 채 뒤로 빼기는 IDLE로만 간다 (반대손도 주먹일 때는 빼기로 보지 않는다). 제스처 모드로 들어온
주먹은 한 번 펴야 IDLE로 뺄 수 있다. ☝️ 톡톡은 어느 모드에서든 커서 모드.

🤟 확대/축소는 커서·제스처 모드 모두에서 macOS 손쉬운 사용의 화면 확대를 단축키(⌥⌘= / ⌥⌘−)로 한 단계씩 부른다. 시스템 설정 >
손쉬운 사용 > 확대/축소에서 "키보드 단축키를 사용하여 확대/축소"를 켜야 동작한다. 합성한 트랙패드
핀치와 ⌃+스크롤은 macOS 26.5에서 아무것도 확대하지 못해서 쓰지 않는다.

데스크톱 전환은 **제스처 모드에서 손바닥을 보인 채 0.6초 멈추면 전용 모드로 들어간다** — 화면 네 변에 보라색
테두리가 생기고 가운데에 안내가 뜬다. 거기서는 좌우로 쓰는 것만 인식하니, 기다리는 동작이 다른 제스처와
겹치지 않는다. 나올 때는 다른 제스처 모양(세 손가락·핀치 등)이나 ✊✊ 양손 주먹으로 제스처 모드, ✊ 뒤로 빼기로 IDLE, ☝️ 톡톡으로 커서 모드.

쓸기는 0.15초 멈췄던 자리에서 옆으로 화면 폭의 13% 이상을 0.8초 안에 움직이면 발동한다. 방향은 멈췄던 자리
기준이라 반대쪽으로 살짝 당기는 준비 동작에 속지 않는다. **연속으로 쓸 때는 다시 멈출 필요가 없다**: 전환 후
3초 동안은 손이 방향을 바꾸는 지점이 다음 쓸기의 출발점이 된다. 되돌아오는 손은 출발점 근처에서 끝나기
때문에 무시되고, 반대로 넘기려면 출발점을 지나 더 쓸면 된다. 오른쪽으로 쓸면 다음 데스크톱, 왼쪽으로 쓸면
이전 데스크톱 — 가려는 쪽을 손으로 가리키는 방향이다 (트랙패드 세 손가락과는 반대).

재생/정지는 **주먹으로 카메라를 두 번 노크**하면 된다 (1.2초 안에 두 번, 손 크기가 15% 이상 커졌다 40%
이상 돌아오는 것으로 잰다 — 사용자의 `knock-knock` 녹화 5개로 맞췄다). 손을 펴면 취소된다. 손바닥으로
하던 동작이었지만 손바닥이 데스크탑 전환 모드를 여는 신호가 되면서 주먹으로 옮겼다. 주먹을 뒤로 빼서
**그대로 두면** IDLE이고, 바로 다시 내밀면 노크다 (뒤로 뺀 상태가 0.25초 이어져야 IDLE로 간다).

**조도가 부족하면** (프레임 평균 밝기가 0.10 이하로 1.5초) 인식을 멈추고 화면 상태를 그대로 둔다. 어두운 방은
카메라에 '사람 없는 방'으로 보여서, 그대로 두면 앞에 앉아 있는 사람의 화면을 까맣게 만들고 잠그는데 정작
얼굴이 안 보여 풀 수도 없다. 그래서 **잠기지 않았으면 잠그지 않고, 이미 잠겼으면 그대로 잠긴 채 둔다**
(Touch ID·암호는 그대로 된다). 밝기가 0.16 이상으로 돌아오면 다시 인식한다. 이 사이에는 Mac의 원래 절전
시간이 적용된다.

메뉴의 "제스처 인식"(⌃⌥⌘G)을 끄면 제스처만 멈춘다 (사용자 요청 2026-09-23). 카메라는 계속 돌아서 자리 비움
화면 끄기·잠금, 보안 모드, 얼굴 해제, 주인만 인식이 그대로 동작한다. 다시 켜면 제스처 모드로 시작한다.

카메라가 돌고 있는 동안 Mac은 디스플레이도 시스템도 잠들지 않는다. 5초 동안 아무도 안 보이면
IDLE로 바뀌고, 10초가 되면 화면이 완전히 까매진다. 화면 보호기도 뜨지 않는다: bitbytebot Mac(화면 보호기
기본 설정, 화면 보호기 5분 뒤 암호 요구)에서 아무도 없이 입력 없는 23분 동안 화면 보호기도 macOS 잠금도
뜨지 않았다 (2026-09-23).

## 까만 화면 잠금

얼굴을 등록하면 까매진 화면이 잠긴다. 잠긴 동안에는 키보드·마우스·트랙패드 입력이 앱에 전달되지 않고,
앞에 사람이 와도 화면이 돌아오지 않는다. 풀리는 방법은 두 가지다.

1. **얼굴** — 등록한 사람 중 누구든 카메라에 1초 안팎으로 여러 번 확인되면 저절로 풀린다.
2. **Touch ID·로그인 암호** — 키를 누르거나 클릭하면 인증 창이 뜨고 화면이 35% 밝기로 올라온다.
   지문이 등록돼 있지 않으면 암호 창이 뜬다. 30초 동안 아무도 답하지 않으면 창이 닫히고 다시 까매진다.
   인증 창이 떠 있는 동안에는 창 안의 클릭과 암호 칸에 치는 키만 통과하게 했다. 암호 칸의 키가 막히지 않는지는
   아직 직접 확인하지 못했다 (보안 입력이 켜졌는지로 판단한다).

**보안 모드** (메뉴바에서 켜고 끈다, 기본 켜짐)는 자리가 2초 넘게 비었다가 누가 나타나면 그 사람이 등록된
사람인지 확인한다. 화면이 까매지기까지 10초를 세는 동안 다른 사람이 앉는 경우를 막는 게 목적이다 (사용자 요청
2026-09-16). 등록되지 않은 얼굴이 또렷하게 다섯 번 연속 (0.25초 간격, 약 1.5초) 잡히면 10초를 기다리지 않고 바로
화면을 까맣게 하고 잠근다. 등록된 얼굴이 한 번 보이면 확인을 끝내고, 얼굴이 안 보이거나 너무 멀거나(화면 높이의
8% 미만) 방이 어두우면 잠그지 않으며, 나타난 지 10초가 지나면 확인을 포기한다. 앉아 있는 동안에는 확인을 돌리지
않는다 — 얼굴 확인 한 번이 손 인식 프레임의 4분의 1쯤을 먹기 때문이다. 몸 인식이 1~2초씩 깜빡여도 확인은 끊기지
않는다. Touch ID·암호로 푼 뒤 2분 동안은 얼굴로 다시 잠그지 않는다 — 카메라가 그 사람을 못 알아보는 상황이니
곧바로 다시 잠그면 갇히기 때문이다. 잠금이 꺼져 있거나 등록된 얼굴이 없으면 보안 모드도 동작하지 않고, 꺼 두면
얼굴 확인 자체를 돌리지 않는다.

처음 실행하면 얼굴 등록 창이 한 번 뜨고, 첫 얼굴을 등록하면 잠금이 켜진다. 여러 사람을 이름을 붙여 등록할 수
있다. 메뉴바 > **얼굴 추가…** 로 사람을 더하고, **등록된 얼굴 N명** 에서 사람마다 **다시 등록…** 이나 **삭제** 를
고른다. **까만 화면 잠금** 으로 켜고 끈다. 사진은 저장하지 않고, 이름과 얼굴에서 뽑은 512차원 숫자 벡터만
`~/Library/Application Support/MotionController/faces.json`에 저장한다. 등록된 사람은 잠긴 동안 사진도 찍히지
않는다.

보안 모드가 모르는 얼굴을 잡아 잠글 때는 그 순간 사진을 두 장 (0.7초 간격) 남긴다 — 얼굴이 카메라 앞에 있는
바로 그때가 가장 잘 찍히기 때문이다. 그 밖에 잠긴 동안 누군가 키보드·마우스·트랙패드를 건드리면 카메라 사진을 찍는다. 그 순간 한 장, 이후 등록되지 않은
얼굴이 보일 때마다 1초 간격으로 최대 두 장 더 찍는다. 15초 안에 등록된 사람의 얼굴이나 Touch ID·암호로 풀리면
주인이었던 것으로 보고 버린다. 아무도 못 풀거나 인증 창이 잠긴 채 닫히면 저장한다. 저장한 뒤 30초 동안은 새로 찍지 않는다.
사진은 `~/Library/Application Support/MotionController/Intruders/`에 쌓이고, 화면이 다시 돌아오면 마지막 사진과
장수를 보여 주는 창이 뜬다. 메뉴바 > **잠긴 동안 찍힌 사진 N장 보기…** 로도 연다.

## 주인만 인식

메뉴바 > **주인만 인식 (다른 사람 동작 무시)** 을 켜면 (사용자 요청 2026-09-21) 화면에 여러 사람이 있어도 등록된
주인의 손만 입력이 된다. 얼굴이 인식되면 그 얼굴이 올라앉은 몸을 주인으로 고정하고, 다음 프레임부터는 머리
위치로 따라간다 (한 프레임에 0.25 image height 이상 튀면 다른 사람으로 본다). 주인 몸에 붙은 손과, 몸에 안 붙었지만
주인 머리에 가장 가까운 손만 통과시킨다 — 카메라에 손을 가까이 들면 어깨가 잘려 몸과 연결이 끊기기 때문이다.

- **혼자 있을 때:** 헷갈릴 사람이 없으니 평소와 똑같이 동작한다. 얼굴 확인도 돌리지 않는다.
- **두 명 이상일 때:** 주인을 찾을 때까지 아무 손도 받지 않고, 오버레이에 "주인 확인 중"이 뜬다.
- **얼굴 확인 주기:** 두 명 이상 보일 때만 초당 4번. 한 번 고정되면 10초 동안은 얼굴 없이도 따라간다.
- **필요 조건:** 등록된 얼굴. 없으면 메뉴에서 꺼진 상태로 보인다.

macOS 잠금 화면을 대신하지 않는다.

- 사진·영상을 들이대면 통과할 수 있다 (눈 깜빡임 같은 생체 확인이 없다).
- 앱을 강제 종료하거나 앱이 죽으면 입력 차단과 까만 화면이 같이 풀린다. 앱이 멈춰도 macOS가 입력 차단을 끈다.
- 카메라가 한 번에 보는 건 가장 큰 얼굴 하나다. 주인 옆에 다른 사람이 더 가까이 서면 그 얼굴로 판정한다.
- 어두운 방에서는 화면이 까매서 얼굴이 잘 안 보인다. 그때는 Touch ID·암호를 쓴다.
- macOS 잠금 화면이 뜨거나 다른 사용자로 전환되면 이 잠금은 비켜난다.

얼굴 인식 모델은 저장소에 없어서 직접 받아야 한다. 없으면 **얼굴 등록 메뉴가 회색으로 꺼져 있고** 잠금도
안 걸린다. 받는 방법은 [빌드](#빌드)의 2번에 있다.

잠금 동작을 확인할 때는 `open --env MC_LOCK_TEST=20 MotionController.app` 으로 켠다. 3초 뒤 누가 있든 잠그고,
20초 (최대 60초) 뒤 저절로 푼다.

## 빌드

Xcode와 Apple ID(무료)만 있으면 된다.

**1. XcodeGen**

```bash
brew install xcodegen
```

**2. 얼굴 인식 모델 (얼굴 등록·화면 잠금을 쓸 거라면 필수)**

저장소에는 **일부러 넣지 않았다** — 코드는 MIT지만 가중치가 학습 데이터(WebFace4M) 때문에 비상업용이라
재배포하지 않는다. `.gitignore`가 `App/Vision/Models/`를 막고 있으니, 새로 클론한 컴퓨터에는 항상 없다.
약 44MB.

```bash
curl -L -o /tmp/AdaFace_IR18.mlpackage.zip https://github.com/john-rocky/CoreML-Models/releases/download/adaface-v1/AdaFace_IR18.mlpackage.zip
```

```bash
mkdir -p App/Vision/Models && unzip -o /tmp/AdaFace_IR18.mlpackage.zip -d App/Vision/Models
```

모델이 없어도 빌드와 나머지 기능은 전부 된다. 대신 **메뉴의 "얼굴 등록"이 꺼진 상태로 보이고** 까만 화면
잠금이 동작하지 않는다. 등록 메뉴가 회색이면 거의 이 파일이 없는 것이고,
`App/Vision/Models/AdaFace_IR18.mlpackage`가 있는지 확인하면 된다. 받은 뒤에는 3번을 다시 해야 앱 번들에
들어간다.

**3. 빌드**

```bash
cd "motion controller" && xcodegen generate && xcodebuild -project MotionController.xcodeproj -scheme MotionController -configuration Debug -derivedDataPath build/DerivedData build
```

`project.yml`의 `DEVELOPMENT_TEAM`은 이 저장소 주인의 팀 ID다. **다른 컴퓨터에서는 본인 팀 ID로
바꿔야 한다** (Xcode > Settings > Accounts에서 확인, 또는 `security find-identity -v -p codesigning`).

빌드된 앱은 `build/DerivedData/Build/Products/Debug/MotionController.app`에 생긴다.

**4. 설치 패키지 (선택)**

```bash
./Scripts/make-installer.sh
```

Release로 빌드해서 `dist/MotionController-<버전>.pkg`를 만든다. `/Applications`에 설치하고, 설치 전에
실행 중인 사본을 종료하며, 설치 화면에 필요한 권한과 첫 실행 안내가 나온다.

**서명은 안 된다.** 이 저장소는 Apple Development 인증서로 서명하고 `Developer ID Installer` 인증서가 없기
때문이다. 이 Mac에서는 그냥 열리지만, 다른 Mac에서는 Gatekeeper가 막으므로 받는 쪽에서 우클릭 > 열기나
`xattr -dr com.apple.quarantine <파일>.pkg`가 필요하다. 유료 Apple Developer Program의 Developer ID
인증서가 생기면 스크립트가 알아서 서명한다 (공증은 별도로 `notarytool`이 필요하다).

설치한 앱과 개발 빌드는 번들 ID가 같아서 설정·등록된 얼굴·얼굴 모델(`~/Library/Application Support/MotionController/`)을
공유한다. 다만 **손쉬운 사용 권한은 실행 파일 위치가 바뀌면 다시 허용해야 할 수 있다** — 설치 후에는
`/Applications` 쪽만 실행하는 게 깔끔하다.

## 실행 — `open`으로만 켤 것

```bash
open "build/DerivedData/Build/Products/Debug/MotionController.app"
```

바이너리를 직접 실행하면 **손쉬운 사용 권한이 적용되지 않아 합성 이벤트가 조용히 전부 무시된다.**
커서도 데스크톱 전환도 아무 로그 없이 동작하지 않으니, 반드시 `open`으로 켠다.

처음 켜면 두 가지 권한을 직접 허용해야 한다.

1. **카메라** — 실행 직후 뜨는 대화상자
2. **손쉬운 사용** — 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용에서 MotionController 추가

처음 실행하면 체험형 사용법이 뜬다. 제스처 모드 들어가기부터 데스크톱 전환, 재생/정지, 확대/축소, 볼륨·밝기,
커서 모드의 이동·클릭·우클릭·스크롤·드래그, IDLE로 쉬기까지 차례로 직접 해 보고, 그 동작이 실제로
인식돼야 클리어된다. 마지막 네 단계는 한 번 정해 두는 것들이다 — 얼굴 등록, **보안 모드**와 **주인만 인식** (둘 다
설명과 함께 창 안에서 바로 켜고 끈다), 커서 영역 보정. 단계에 맞는 모드가 아니면 어떻게 들어가는지 알려 주고, 단계마다 건너뛸 수 있다. 시작할 때
IDLE로 바뀐다. 마지막에 키보드 단축키와 자리 비움·잠금 동작을 정리해 보여 준다. 메뉴바 > **사용법 보기…** 로
다시 연다.

서명은 Apple Development 인증서로 고정돼 있다. ad-hoc 서명은 빌드마다 서명이 바뀌어서 손쉬운 사용
권한이 매번 초기화된다.

## 커서 영역 보정

메뉴바 > **커서 영역 보정…** 을 누르면 화면 네 모서리에 표적이 뜬다. 검지로 각 모서리를 가리키고 0.8초
멈추면 측정되고, **화면 아래 버튼**(다시 측정 / 다음 모서리 / 완료 / 취소)을 눌러야 다음 모서리로 간다 —
자동으로 넘어가면 다음 모서리로 가는 손이 이미 측정되고 있었기 때문이다. **네 모서리를 두 번 돌아 평균**을
쓴다. **커서 영역 기본값으로** 로 되돌린다.

## 손을 찾는 방식

손은 `DetectHumanHandPoseRequest`(손 전용 요청)로 매 프레임 찾고, 몸은 10fps로만 찾는다. 몸에 딸려 오는
손(`DetectHumanBodyPoseRequest(detectsHands:)`)을 쓰지 않는 이유는, 손을 얼굴이나 가슴 앞에 두면 몸 인식이
사라지면서 손도 같이 사라지기 때문이다.

**작은 손은 잘 안 잡힌다.** 화면 높이의 0.15만 한 검지 손은 프레임의 **35~40%에서 아예 안 잡혔고**, 0.26만 한
손바닥은 **하나도 놓치지 않았다**. 손을 카메라 쪽으로 조금 더 내밀거나 화면 중앙 높이로 올리면 체감이 크게
달라진다.

손 주변만 잘라서 인식하는 방법은 **측정해 보고 접었다** (`HandSource`의 주석에 표가 있다). 같은 프레임에서:
전체 화면은 손을 찾고 28.8ms, `regionOfInterest`를 준 두 방식은 손이 영역 안에 있는데도 **아무것도 못 찾고**,
`CIImage`로 실제로 잘라 넣으면 찾지만 **271.5ms**(10배)가 든다.

해상도를 올리는 방법은 안 된다: 이 카메라는 1920×1080 30fps를 지원하지만 Vision이 프레임당 20ms → **79ms
(14fps)**가 된다. 몸+손 요청을 빈 프레임에만 덧붙이는 방법도 40~70ms가 들어 **15fps**로 떨어졌다.

## 개발

```bash
cd Packages/GestureCore && swift test
```

제스처 판정 로직은 전부 `Packages/GestureCore`에 순수 Swift로 있고, 사용자가 직접 녹화한 랜드마크
시퀀스(`Tests/GestureCoreTests/Fixtures/sequences`)로 회귀 검증한다. 디버그 프리뷰 창의 "3초 녹화"
버튼이 그 fixture를 만든다 — 좌표만 저장하고 영상은 저장하지 않는다.

녹화를 분석하는 환경변수들이 `Tests/GestureCoreTests/RecordingTraces.swift`에 있다.

```bash
cd Packages/GestureCore && SWIPE_RUNS=1 swift test --filter printSwipeRuns
```

```bash
cd Packages/GestureCore && SWIPE_COUNTS=1 swift test --filter printSwipeCounts
```

`PRINT_TRACES=<라벨>`은 프레임별 판정을, `RENDER_HANDS=<라벨>`은 랜드마크 그림을 뽑는다.

## private API

개인용이라 쓰지만 macOS 업데이트로 깨질 수 있다. 각각 없으면 그 기능만 꺼진다.

- 데스크톱 전환: Dock-swipe CGEvent의 비공개 필드 (합성 ⌃←/⌃→는 macOS가 무시한다)
- SkyLight `SLSCopyManagedDisplaySpaces`: 현재 Space 목록 읽기 전용
- 밝기 fallback: DisplayServices

차용한 코드의 라이선스 고지는 `THIRD_PARTY_NOTICES.md`에 있다.
